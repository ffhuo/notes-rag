# notes-rag

[English](README_EN.md) | [简体中文](../README.md)

> A self-hosted knowledge base app (RAG) — turn your Markdown / plain-text notes (an Obsidian vault or any directory) into a **searchable, Q&A-ready Web application** (backend API + frontend UI).
> Vaults are configured in the web UI (add a local directory / upload a vault `.zip`); multi-user support is controlled by a config switch (single-user by default).
> Configure **multiple LLMs / multiple Embedding models** and choose per use: the LLM can be switched on every request; the Embedding model is bound to the index, so switching requires re-indexing (see module index M08 in `DESIGN_EN.md`).
> Supported parsers: `.md` / `.txt` / `.docx` / `.pdf` / `.xlsx` (scanned PDFs go through a multimodal LLM), plus file/folder filtering (module index M11).
> The repo ships a layered architecture with a **design overview**: `DESIGN_EN.md` (architecture / layout / choices / data flow / API / data model / config / conventions / module index) — implement the business logic step by step from the docs, or deploy it directly as a self-hosted knowledge base.

> The backend business logic is fully implemented (routes / services / repositories / RAG layers complete). The demo is only a zero-dependency preview of the interactions; the real backend is the source of truth.

## Tech Stack

- FastAPI + Uvicorn (async web framework)
- Pydantic v2 + pydantic-settings (validation and config)
- SQLAlchemy 2.0 (async) + aiosqlite (metadata / chat history; SQLite runs in WAL mode)
- Chroma (local persistent vector store; collections isolated as `v{vault}_m{profile}`)
- openai SDK (OpenAI-compatible endpoints: Qwen, SiliconFlow, or any compatible service)
- python-docx + PyMuPDF + openpyxl (`.docx` / `.pdf` / `.xlsx` parsing); Pillow (local image size / format checks)
- loguru (structured logging with rotation, retention, and level config)
- MCP Python SDK (FastMCP; agent integration see `MCP_GUIDE_EN.md`)
- **Vue 3 + Vite** (frontend SPA: Vault management / tasks / search / chat / model management — design summary in `DESIGN_EN.md` module index M07)
- **uv** (Rust-based, extremely fast Python package manager, standard PEP 621); tests use pytest + pytest-asyncio

## Setup (uv)

> Install uv first (either one):
> - `python -m pip install uv`
> - or the official script: `curl -LsSf https://astral.sh/uv/install.sh | sh`

**Dependencies are installed from the official PyPI by default**; on mainland-China networks you can point at a mirror:
`make sync UV_INDEX=https://mirrors.aliyun.com/pypi/simple/` (the `Makefile` injects it into `UV_DEFAULT_INDEX`, which takes priority over config files; personal preferences can go into an untracked `uv.toml`).
> Note: the Tsinghua TUNA mirror has recently returned 403 for some wheels and is not recommended.

```bash
cd notes-rag

# 1. Resolve + install dependencies, create the in-project venv (./.venv), write uv.lock
make install            # equivalent to uv sync --python 3.12

# 2. Configure environment variables
cp .env.example .env    # adjust API_KEY / ingestion filters as needed; model config lives in the "Models" page (.env no longer carries model config)

# 3. Initialize SQLite tables (the app also creates tables on startup; this is for manual setup)
make init-db
```

After `uv sync`, prefix commands with `uv run` (auto-activates .venv):

```bash
uv run python -m app.main
uv run uvicorn app.main:app --reload
uv run pytest
```

## Running

### Locally

```bash
# Option 1: module
uv run python -m app.main

# Option 2: uvicorn (recommended, hot reload)
uv run uvicorn app.main:app --reload
```

- Web UI: `http://127.0.0.1:8000/` (run `make frontend-build` first to produce `app/static`).
- Interactive API docs: `http://127.0.0.1:8000/docs` — **only when `DEBUG=true`** (off by default; see the `docs_url` switch in `app/core/config.py`).

### Docker (server / remote access)

**One image, one container, one port**: the frontend is built by Vite into the same image and served same-origin by FastAPI — **no separate nginx container needed**.

```bash
# Build and start (data persisted to ./data, logs to ./logs, listening on 0.0.0.0)
make docker-build
make docker-up          # equivalent to docker compose -f deploy/docker-compose.yml up -d --build
make docker-down        # stop

# or plain docker run
docker run -d --name notes-rag -p 8000:8000 \
  -v $(pwd)/data:/app/data -v $(pwd)/logs:/app/logs \
  --env-file .env -e HOST=0.0.0.0 notes-rag
```

Image and compose highlights:

| Item | Detail |
| --- | --- |
| Multi-stage build | Stage 1 uses `node:20-alpine` to run `npm ci && npm run build` (output to `app/static`); Stage 2 uses `python:3.12-slim` + `uv sync --no-dev`, copying assets for FastAPI to serve |
| Port | `8000` in-container; `HOST=0.0.0.0` injected by compose (local defaults to `127.0.0.1`) |
| Data/log volumes | `../data → /app/data` (Chroma + SQLite + uploads), `../logs → /app/logs` |
| Health check | `healthcheck` probes `/healthz`; `docker compose ps` shows healthy |
| Production defaults | compose forces `DEBUG=false` (no `/docs`, no SQL echo); override in compose `environment` for debugging |

- Remote access must go through a **reverse proxy + HTTPS + API Key** (see M10's remote-access checklist); template at [deploy/nginx.conf.example](../deploy/nginx.conf.example) (SSE buffering disabled).
- When `UI_ENABLED=true` and `app/static` exists, the backend mounts `/assets` and provides SPA fallback for frontend sub-routes (e.g. `/tasks`); unmatched `/api/*` still returns 404.

### Frontend Pages (Vue 3 + Vite SPA)

Frontend source is in `frontend/`, with routes `/vaults` (Vault management) / `/tasks` (jobs & progress) / `/search` / `/chat` / `/models`; **login / register / API Key entry are handled by global dialogs, no dedicated login page** (see M07).
The chat page supports **voice input** (browser recording → `POST /api/v1/audio/transcribe`; requires an `kind=asr` model configured first, otherwise 409).
The "Tasks" page (`/tasks`) is the observation entry for async indexing jobs: the progress bar adapts to the stage (a rolling bar instead of a fake percentage while `scan` doesn't know the total),
filtering by vault / status, expandable sync plans and failure lists, and cancellation at any time.

```bash
# Development (separated): Vite dev proxies /api → backend :8000
make frontend-install
make frontend-dev          # open http://127.0.0.1:5173

# Build the frontend into app/static (served by FastAPI, same origin, no CORS)
make frontend-build
# then start the backend and visit http://127.0.0.1:8000/
```

### Vault Configuration & Indexing Jobs (managed in the UI)

Vaults are configured entirely at runtime via the UI / API, **not in `.env`**: on the "Vaults" page you can **add a local directory** (absolute path) or **upload a vault `.zip`**, stored in the `vaults` table. Without the UI, use the API: `POST /api/v1/vaults` to create → `POST /api/v1/vaults/{id}/sync` to submit a job; one-shot ingestion via `POST /api/v1/ingest` (body `vault_sources: ["local:/abs/path"]`) (see M06).

**All indexing is asynchronous** (`POST /vaults/{id}/sync` / `/reindex` → `202 + run_id`):

- Submission returns immediately — it does **not** wait for completion (a full rebuild takes 2–10 min; a synchronous response would always hit gateway timeouts). Progress is visible live on the "Tasks" page (`/tasks`),
  via `GET /vaults/{id}/runs/{rid}`, polled at 1s by the frontend.
- **Sync** (incremental reconciliation): for daily use, processes only changed files, usually seconds. Supports "preview changes" — submit a `dry_run` job;
  it stops at `plan_ready` so you can review which files would change before executing.
- **Reindex** (full rebuild): only when switching embeddings / changing chunk parameters / when the index looks corrupted.
- Submitting while a job is already running for the same vault returns **`409` + `existing_run_id` (no queueing)**; the frontend jumps straight to that job's progress.
- Jobs can be cancelled anytime (`POST .../cancel`): **cooperative** — it stops after the current file finishes (file-level replacement is the idempotent unit, so stopping at boundaries is naturally consistent).
- Seven statuses; `failed` (program error) / `cancelled` (user-initiated stop) / `aborted` (crash leftover) have distinct semantics — don't mix them up when debugging.

### Multi-user (optional, off by default)

`.env` switch `ENABLE_MULTIUSER` (default `false`):

- **false (single-user)**: everything belongs to `user_id="default"`; APIs authenticate via `X-API-Key`; no login page (enter the API Key once in settings).
- **true (multi-user)**: enables the `users` table + JWT (`JWT_SECRET` required); the frontend shows a Login page; protected APIs accept both `X-API-Key` and `Bearer <JWT>`; vaults / conversations are isolated per user (see M06).

### Multi-model (multiple LLMs / Embeddings, selectable per use)

Model configuration (LLM / Embedding / ASR) lives entirely in the `model_profiles` table — **`.env` no longer provides model config** (no fallbacks); the "Models" page can create/edit/delete, set defaults, and test connections.

- **LLM**: stateless — **switchable on every request** (`ChatRequest.llm_profile`, a dropdown on the chat page).
- **Embedding**: strongly bound to the index — vectors are split into collections by `v{vault}_m{profile}`, so retrieval must use the same model that built the index; switching = reindex that vault (`POST /vaults/{id}/reindex?embed_profile=...`). The API **deliberately does not expose** `SearchRequest.embed_profile`, avoiding the silent failure of "recalls results but all noise".

See `DESIGN_EN.md` module index M08.

### Voice Input (optional, requires an ASR model)

The chat page can record and transcribe: browser MediaRecorder → `POST /api/v1/audio/transcribe`. Transcription uses a `kind=asr` model from `model_profiles` — **no `.env` fallback**; if unconfigured the API returns **409** pointing to the "Models" page.

- Protocol branches on `params.protocol`: `dashscope_native` uses DashScope's native `multimodal-generation` synchronous endpoint; everything else (including default) uses the standard `/audio/transcriptions`.
- Tested: SiliconFlow (`api.siliconflow.cn/v1` + `FunAudioLLM/SenseVoiceSmall`) works via the standard endpoint; Alibaba Bailian requires `dashscope_native`, and the browser-default `webm/opus` may be rejected there (400).

### Image Indexing (multimodal, automatic)

Images inside documents are described by a multimodal model during indexing and re-inserted into the text for retrieval and Q&A:

- **No separate switch**: processed only when the LLM config used for that indexing run has `params.multimodal=true`.
- Local images: dimensions ≥ 200px, size ≤ 5MB each, path must be inside the vault root; remote `http(s)` links are passed straight to the model (no download, no validation).
- Results are cached in the `image_cache` table by `(user_id, content_key)`; changes to a remote URL's content are not detected automatically — re-index to refresh.

## Dependency Management (uv)

| Action | Command |
| --- | --- |
| Add a runtime dependency | `uv add fastapi` |
| Add a dev dependency | `uv add --group dev pytest` |
| Remove a dependency | `uv remove fastapi` |
| Upgrade all (re-resolve) | `uv lock --upgrade` |
| Re-resolve the lock only | `uv lock` |
| Install locked dependencies | `uv sync` |

> Note: `uv.lock` should be committed for reproducible environments; `.venv/`, `data/`, `.env` are already gitignored.
> uv uses the standard PEP 621 format; the project is an app, not a publishable library — `[tool.uv]` sets `package = false`.

## Agent Integration (MCP / Skill)

The project can be used as a knowledge-base tool by agents (WorkBuddy, OpenClaw, etc.) — see **`MCP_GUIDE_EN.md`** for setup; design summary in `DESIGN_EN.md` module index M09:

- **MCP server (main path)**: `app/mcp/server.py` wraps retrieval / Q&A as standard MCP tools; agents connect via `mcp.json`. Two transports: **stdio (recommended locally, zero ports)** and **Streamable HTTP (for server deployments and remote agents)**.
- **Skill (zero-deployment fallback)**: a `skill/SKILL.md` text instruction lets skill-capable agents call the REST API directly.
- **Two run modes**: local mode keeps data on your machine — stdio MCP is the simplest; server deployment (Docker) serves remote access — MCP goes over Streamable HTTP + API Key (see M09 / M10). Run `uv sync` before enabling (`mcp` is already in pyproject).
